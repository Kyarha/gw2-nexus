- [2026-08-14] **Coordinate model: design brief vs. spec — a real scope divergence (triage for spec 003).** The CD design brief [design/notes/notes-v1.0.md](design/notes/notes-v1.0.md) (on branch `claude/notes-spec-003-brief-967e61`, not yet on main) models coordinates as **inline clickable links embedded in a note's freeform text** — e.g. `[Diessa Plateau — 4200, 8600]` mid-sentence, potentially **several per note**, each a pin-glyph link offering Show-on-map / Share-to-chat. That implies **parsing coordinates out of the note body**. The built spec (003-02 + 003-04) instead models **one optional coordinate per note, captured from the live player position** ("Stamp here"), shown as a separate field with Show-on-map / Copy actions — **no text parsing**. The *actions* (Show-on-map / Share-to-chat) match; the mismatch is **where the coordinate comes from (author-typed vs. position-stamped) and how many a note can carry (many-inline vs. one-stamped)**. Decide whether spec 003 adopts the brief's inline-in-text model, keeps the stamp model, or supports both (e.g. inline parsing as a fast-follow slice). Surfaced this session while reading the brief; not yet resolved. Related: [ADR-0005](decisions/adr-0005-coordinate-action-mechanism.md) (the actions), slice 003-04.

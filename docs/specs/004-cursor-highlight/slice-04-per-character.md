## Slice 004-04 — per-character settings

> **ABANDONED (2026-08-20).** Considered and deliberately dropped for v1.0. The
> Settings mockup showed "save per character", but cursor preferences are
> effectively identical across characters (unlike notes), so v1.0 ships **one
> shared profile** (persisted globally in 004-01). Recorded here for the decision
> trail; the AC/DoR below are the shape it *would* have taken, kept for reference.

**Abandonment reason:** Per-character cursor settings add a MumbleLink identity
read and a migration for negligible value — cursor look/behaviour is the same on
every character. v1.0 uses one shared profile (owner decision, 2026-08-20).

**Goal:** Honor the mockup's "**Settings apply instantly and save per
character**": key the cursor settings record by the current character's identity
and auto-load the right profile when the active character changes, mirroring
Notes' per-character model (UC-10, slice 003-05).

**DoR (Definition of Ready):**
- ✅ 004-01 DONE — the versioned settings record + persistence exist.
- ✅ Character identity read pattern established by Notes 003-05 (MumbleLink
  identity / `Name`), available to reuse.

**Acceptance Criteria:**

1. **Settings key by character.** The settings record stores a per-character
   profile keyed by the current character identity (spec A4); saving writes to
   that character's profile (schema version bumped + migrated from the single-
   profile 004-01 record — existing settings become the first character's, or a
   shared default, with no data loss).
2. **Auto-load on character change.** When the active character changes (detected
   via the identity read), the panel + marker switch to that character's saved
   profile without a reload. Always reachable — this never *gates* the panel, it
   only selects which profile is shown (design principle #2).
3. **Sensible default for a new character.** A character with no saved profile
   gets the v1.0 defaults (or an explicit "shared default" if that path is
   chosen), defined and tested in `cursor-core`.
4. **Safe when identity is unavailable.** If MumbleLink identity is missing/not
   live, fall back to a single default profile rather than losing or corrupting
   settings.

**Assumptions (per-slice, drives `frame_review`):**
- **A4 (this slice) — character identity is readable + stable.** The identity
  field/encoding from MumbleLink (used by Notes 003-05) uniquely identifies a
  character for keying. Confirmed at implementation against the live link; the
  exact field is verified in-game before relied on.

**DoD:**
- [ ] All ACs pass; full suite green.
- [ ] `cursor-core` tests cover per-character keying, the single→per-character
      migration, new-character defaults, and the identity-unavailable fallback;
      each shown red→green.
- [ ] Reviewed by `reviewer` subagent (compliance + craft).
- [ ] Deviation log + reconciliation sweep produced.

**Anti-horizontal-phasing check:** After this slice each character remembers its
own cursor look and behaviour, switching automatically when the player swaps
characters — a visible, per-character convenience.

> **Note.** May be parked `DEFERRED` if a single shared profile proves preferable
